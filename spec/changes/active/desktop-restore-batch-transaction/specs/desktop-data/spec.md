# Spec Delta: 备份恢复批量事务（desktop-data 域）

### FR-RSTO-001 恢复耗时降到亚秒级
恢复一份与当前实测同规模（约百级 Prompt、数百版本）的备份，prompt 图写入阶段必须在 1 秒内完成；工作区文件只重建一次，不得随删除条数线性增长重建次数。

### FR-RSTO-002 恢复结果与逐条路径等价
批量恢复后的数据库内容必须与既有逐条路径一致：Prompt / 文件夹 / 版本 / 关系 / 输出格式的全部 ID 与字段保真，父子顺序保持（子项先于父项到达也要正确落库），`folder_id` 与 `parent_id` 引用不因清空顺序而丢失。

### FR-RSTO-003 原子性
写入必须在一个 SQLite 事务内完成。任一条记录失败时整次回滚，数据库保持恢复前状态，不得出现「旧数据已清空、新数据只写了一半」的状态；调用方收到结构化失败原因。

### FR-RSTO-004 输入边界
主进程必须拒绝非对象入参、缺失集合、以及集合中存在非对象元素的情况；空数组按「该集合为空」处理而非报错（前置的备份有效性判定仍在渲染层 `hasMeaningfulBackupContent` 负责）。

### FR-RSTO-005 不可用时退回既有路径
运行环境未暴露 `prompt:restoreBatch` 时（例如 Web 运行时），恢复必须继续走原有 IndexedDB / 逐条路径，行为不变。

### MOD-RSTO-001 恢复后的其余阶段不变
媒体 base64 落盘、rules / skills / MCP / plugin 恢复、恢复完成后的界面刷新维持现状，本变更只替换 prompt 图的清空与写入。
