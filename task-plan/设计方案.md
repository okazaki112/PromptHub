# 快捷恢复备份 - 设计方案

## 需求概述
实现将导出的 `.phub.gz` 备份压缩包拖到程序窗口即可恢复备份的功能。

## 技术方案

### 架构决策
采用 **纯 Renderer 端实现**，原因：
1. 现有 `restoreFromFile(file: File)` API 已完整支持文件恢复
2. HTML5 File API 可直接读取拖拽的文件
3. 无需新增 IPC 通道，减少复杂度
4. 与现有导入逻辑完全复用

### 实现位置
在 `App.tsx` 中添加全局拖拽监听，因为：
- 应用根组件，生命周期贯穿整个应用
- 已有类似的剪贴板检测逻辑可参考
- 可以控制全局 UI 状态（显示/隐藏拖拽覆盖层）

### 交互流程

```
用户拖拽文件到窗口
    ↓
检测文件类型 (.phub.gz)
    ↓
显示拖拽覆盖层（视觉反馈）
    ↓
用户释放文件
    ↓
预览备份内容 (previewImportFile)
    ↓
显示确认对话框
    ↓
用户确认
    ↓
执行恢复 (restoreFromFile)
    ↓
显示恢复结果 (Toast)
    ↓
刷新数据 (fetchPrompts, fetchFolders)
```

### 核心代码结构

#### 1. 状态管理
```typescript
// 拖拽状态
const [isDraggingBackup, setIsDraggingBackup] = useState(false);
const [pendingBackupFile, setPendingBackupFile] = useState<File | null>(null);
const [pendingBackupPreview, setPendingBackupPreview] = useState<ImportPreviewSummary | null>(null);
const [showRestoreConfirmDialog, setShowRestoreConfirmDialog] = useState(false);
```

#### 2. 拖拽事件处理
```typescript
// 检测是否为备份文件
const isBackupFile = (file: File): boolean => {
  return file.name.endsWith('.phub.gz') || file.name.endsWith('.phub');
};

// dragover: 检测文件类型，显示视觉反馈
const handleDragOver = (e: DragEvent) => {
  e.preventDefault();
  const files = Array.from(e.dataTransfer?.files || []);
  if (files.some(isBackupFile)) {
    setIsDraggingBackup(true);
  }
};

// drop: 处理文件释放
const handleDrop = async (e: DragEvent) => {
  e.preventDefault();
  setIsDraggingBackup(false);
  
  const backupFile = Array.from(e.dataTransfer?.files || []).find(isBackupFile);
  if (backupFile) {
    // 预览备份内容
    const { summary } = await previewImportFile(backupFile);
    setPendingBackupFile(backupFile);
    setPendingBackupPreview(summary);
    setShowRestoreConfirmDialog(true);
  }
};
```

#### 3. 确认对话框
复用现有的 `ConfirmDialog` 组件，显示：
- 备份文件名称
- 备份内容统计（prompts、folders、skills 等数量）
- 警告信息：恢复将覆盖现有数据

#### 4. 执行恢复
```typescript
const handleConfirmRestore = async () => {
  if (!pendingBackupFile) return;
  
  try {
    await restoreFromFile(pendingBackupFile);
    showToast('备份恢复成功', 'success');
    // 刷新数据
    await fetchPrompts();
    await fetchFolders();
  } catch (error) {
    showToast(`恢复失败: ${error.message}`, 'error');
  } finally {
    setShowRestoreConfirmDialog(false);
    setPendingBackupFile(null);
    setPendingBackupPreview(null);
  }
};
```

### UI 设计

#### 拖拽覆盖层
- 半透明黑色背景 (`bg-black/50`)
- 居中显示图标和文字
- 文字："释放以恢复备份"
- 边框高亮提示

#### 确认对话框
- 标题："确认恢复备份？"
- 内容：
  - 文件名
  - 备份内容统计表格
  - 警告：此操作将覆盖现有数据
- 按钮："取消" / "确认恢复"

### 错误处理

| 场景 | 处理方式 |
|------|----------|
| 文件格式错误 | Toast 提示"不支持的文件格式" |
| 备份内容为空 | Toast 提示"备份文件为空" |
| 恢复过程中出错 | Toast 提示具体错误信息 |
| 用户取消 | 关闭对话框，无操作 |

### 安全考虑
1. **必须用户确认**: 恢复前显示确认对话框，防止误操作
2. **数据覆盖警告**: 明确告知用户将覆盖现有数据
3. **文件类型验证**: 仅接受 `.phub.gz` 和 `.phub` 文件
