# 发现记录: 快捷恢复备份功能

## 研究发现

### 现有备份系统分析

#### 1. 备份文件格式
- **扩展名**: `.phub.gz` (gzip 压缩的 JSON)
- **内容格式**: `PromptHubFile` 类型，包含 `kind` 字段区分备份类型
  - `prompthub-backup`: 完整备份
  - `prompthub-export`: 选择性导出
- **解析入口**: `database-backup-format.ts` 中的 `parsePromptHubBackupFile()`

#### 2. 现有恢复流程
- **前端服务**: `database-backup.ts` 中的 `restoreFromFile(file: File)`
- **流程**: 
  1. `readBackupFileText(file)` - 读取文件内容（支持 .gz 和 .zip）
  2. `parsePromptHubBackupFile(text)` - 解析并验证备份格式
  3. `importDatabase(backup)` - 导入数据到数据库
- **UI 入口**: 设置页面的数据导入功能

#### 3. 关键 API
- `previewImportFile(file)` - 预览备份内容
- `restoreFromFile(file)` - 执行恢复
- `importDatabase(backup)` - 核心导入逻辑

### Electron 拖拽文件机制

#### Renderer 进程处理方式
- 使用标准 HTML5 拖拽事件: `dragover`, `dragleave`, `drop`
- 通过 `event.dataTransfer.files` 获取文件列表
- 使用 `FileReader` 或 `file.arrayBuffer()` 读取文件内容
- **无需 Main 进程参与** - 可以直接在 Renderer 处理文件

#### 实现要点
1. 阻止默认行为: `event.preventDefault()`
2. 设置拖拽效果: `event.dataTransfer.dropEffect = 'copy'`
3. 文件验证: 检查 `.phub.gz` 扩展名
4. 视觉反馈: 拖拽时显示覆盖层提示

## 技术决策依据

### 方案选择: 纯 Renderer 端实现
**原因**:
1. 现有 `restoreFromFile(file: File)` API 已完整支持文件恢复
2. HTML5 File API 可直接读取拖拽的文件
3. 无需新增 IPC 通道，减少复杂度
4. 与现有导入逻辑完全复用

### 交互设计
1. **拖拽检测**: 监听 `dragover` 事件，检测文件类型
2. **视觉反馈**: 显示半透明覆盖层，提示"释放以恢复备份"
3. **确认对话框**: 恢复前要求用户确认（防止误操作覆盖数据）
4. **进度提示**: 使用现有 Toast 系统显示恢复结果
